# 方法与数据契约

## 1. Turn20 与历史资格

`watermelon.ranking.rank_universe` 接收完整历史时点代码清单 `Coverage`、每个代码的 `SecurityState`、历史 `TurnoverBar` 和最后 20 个市场交易日。适配器须提供当时全 A 股池及明确排除项，不可把历史入选过的 1,134 个存储代码当作全池。

| 输入 | 单位 / 责任 |
|---|---|
| `Coverage.as_of / expected_codes / full_pool_verified` | 该时点完整股票池声明，代码逐个覆盖且不重复；由数据适配器核验来源 |
| `SecurityState.as_of / pit_verified` | 状态在信号日当时可知，包括上市、已知退市日、板块、ST、停牌和股票类型 |
| `TurnoverBar.day / pit_verified` | 指定市场日的一条可核验历史记录；不能用当前股本回填 |
| `turnover_pct` | 已核验当日换手率，百分数，例如 1 表示 1% |
| `volume / float_shares` | 都以股为单位；未给当日换手率时用当日有效流通股本计算 `volume / float_shares * 100` |
| `close / total_mcap` | 正的未复权收盘价 / 同口径总市值；日期和价格单位由适配器统一 |

窗口必须是严格递增、无重复的 20 个实际市场交易日，记录日期集合必须完全一致。有明确记录的停牌或零成交日计入这 20 条记录，但不计入平均分母，例如 18 个有效日就除以 18。活跃日缺换手率且无有效流通股本、缺记录、未知停牌状态或异常值会抛出 `DataQualityError`，不会补零或伪装停牌。全部无效成交时 score 为未知而不是零。

先按 double 累加和取平均，再用标准库转换为 binary32，按 `(score, code)` 升序排序。资格条件为：非北交所的 A 股，历史时点非 ST、非停牌，有效成交，上市至少 365 自然日，信号日早于当时已知退市日，close、total_mcap 为正。已核实的 `known_delisting_date=None` 表示当时没有已到的已知退市日；不能省略生命周期核验。未来知道的状态不得回填。

代码核验清单内部的完整性，无法凭一个候选子集证明“这是全市场”。`full_pool_verified` 是适配器的证据责任。可能合格股票的关键字段未知，会阻断整份排名；明确不合格股票可以没有其价格历史。股票池不足十个合格标的就返回实际数量。`Ranking` 保留全部合格股票，不把未知排名解释为已经落出观察区。

## 2. 收盘信号、次日开盘和实仓

`Ranking.signal_index=t` 指市场日序号，`make_plan(..., execution_index=t+1)` 才合法。交易日序号映射由日历适配器负责，周末、假期不得当作交易日计龄。排名仅使用截至 t 收盘的数据，趋势也只使用该时点已知 close/pre_close；`OpenQuote` 接口不接收执行日收盘价或全日成交量。

实仓年龄是 `execution_index - entry_index`，`entry_index` 来自第一次实际买入成交。age=29 时即使排名 16 也保留；age=30 且排名 16 才给退出意图。rank=10、15 都保留。最短持有期不是强制到期卖出；无排名但已核实不合格的已有 ST，仍遵守原冻结规则。

`Plan` 区分：

- `retained`：保留当前股数，不补齐、不重复新买。
- `exit_intents`：退出请求，尚未卖出的股票依然是实仓。
- `cancel_pending`：原动态规则的待卖股又满足保留条件，可以取消旧退出请求。
- `entry_candidates`：只来自信号日 Top10、且不与当前实仓重复的条件新候选。11—15 名不补新仓。

`slots_before_fills` 基于真实仓位数量。`ready_entries` 接收已确认成交后的仓位，未成交、部分卖出的旧股票仍占一个名额。调用方负责保存待卖状态并落实取消请求；本模块不暗改输入。只有 `record_fill` 接收外部真实回报后才更新股数，零成交不创建时钟，部分成交不重置首次买入日。其最近买入子数量在当天不可卖；完整 FIFO 成本与红利税批次仍在账本适配器中维护。

扩展实验若已经触发弱化待卖，`pending_exit="weakening"` 不可撤销；这与基线 `pending_exit="baseline"` 可取消的语义不同。默认策略不会自动创建弱化退出状态。

## 3. 预算、成本与数量估算

开盘新候选每只含费预算为：

```text
available = actual_cash - frozen_cash
budget = min(available / 新候选数, 开盘可观测净资产 / 10)
```

开盘净资产含全部实仓（含待卖）、实际现金和已形成应收；应收不成为可花现金。开盘无法成交的持仓仍须有已核验标记价格，不能静默漏掉市值。`opening_nav` 对缺标记报错。实际现金不会每天补回初始资金。

调用 `estimate_entries` 前可以处理已确认的卖出，再传入实际现金和仓位。卖出估算、预计卖款、未到账股息不可作为现金传入。分母用这份计划中尚未持有的新候选数，即使部分候选最终受仓位或成交限制阻断，也不把其预算分配给其他股票。批量估算按顺序预留预计买款和名额，返回的是委托估算，不更新真实账户；之后必须由实际回报释放/调整预留。

`estimate_order` 仅用开盘已知状态、开盘价、当时已知涨跌停价、前一市场交易日成交额及实际仓位。未知状态或限价、停牌、涨停买入、跌停卖出、T+1、资金或合法手数不足会返回 0 数量和原因。前日成交额不能换成执行日成交额，也不能向前寻找最近有成交的一天。非法调用（如超卖）抛异常。

买入普通股票至少 100 股、100 股递增；STAR 至少 200 股、之后 1 股递增。普通股票部分卖出按 100 股，STAR 按 1 股，完整余股清仓允许。买入按含费预算与容量较小值保守估算；卖出按成交额容量限制股数。单边滑点按 10bp 并夹在限价内；原研究限价比较容差为 0.004 元。

佣金按每笔 `max(成交额 × 0.0002, 5)`，显式计入单边转让费用和卖出印花税。配置中的卖出印花税 0.0005、双边过户费各 0.00001 仅是 2024—2026 研究参数；真实历史/未来费率、价格档位与费用舍入须由适配器提供。估算使用 Decimal，费用保留计算精度，不冒充券商分笔四舍五入后的账单。

## 4. 调用顺序与完整账本边界

1. 日历和 PIT 适配器提供信号日全池状态及 20 日记录，调用 `rank_universe`。
2. 用实仓及真实首次成交日调用 `make_plan`，下一个市场日开盘才执行。
3. 执行适配器处理退出请求；只有真实回报更新现金、可用资金、持仓与冻结。
4. 传入实际账户和开盘可观测标记，调用 `estimate_entries`；买入回报再调用 `record_fill` 并更新外部账本。
5. 外部账本处理除权、送转、股息应收及到账、FIFO 红利税和潜在未发生税；将调整后的真实整数股、现金和应收传回。

本内核不提供公司行动/现金税账、全历史回测循环、交易所日历或实盘接入。函数等价性、合成路径正确，不代表已经独立复现历史现金收益。扩展适配器时，须保持计划、估算、成交与会计分层，验证整条账户恒等式后再报告收益。
